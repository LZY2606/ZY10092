# TileForge

TileForge 是一个从零实现的本地离线测绘瓦片登记、统一索引、候选拼接和发布系统。后端、HTTP API、持久化和网页都在本仓库内，页面不会写死任何示例数据。

## 启动

```bash
go mod download
go test ./... -count=1
go run ./cmd/server --listen 127.0.0.1:5218
```

浏览器打开 `http://127.0.0.1:5218`。默认数据目录是 `./.tileforge-data`，也可以用 `--data` 指定。

## 地理语义

- 统一输出索引用 EPSG:4326、XYZ：z=0 为 2 列 × 1 行，z 每增加一级行列翻倍。
- 输入支持 `EPSG:4326` 或 `EPSG:3857`，瓦片方向支持 `xyz` 或 `tms`；TMS 只按该 CRS 的网格高度翻转 Y。
- 越界 `x/y` 会进入 `isolated` 清单，不做 `% width`、`% height`，因此不会被错误折到地球另一侧。
- 跨反子午线用 `west > east` 表示，例如 `west=170,east=-170`；系统内部拆成 `[170,180]` 与 `[-180,-170]` 两个非跨缝范围。
- EPSG:3857 只能表示约 `85.0511288°S..85.0511288°N`；声明超出该范围的 Web Mercator 包会被拒绝。EPSG:4326 统一网格可表示到 ±90°，无候选的极区输出瓦片标记为空洞。

## 离线包格式

上传 ZIP，根目录包含 `manifest.json` 和瓦片 PNG：

```json
{
  "name": "survey-a",
  "version": "2026-09",
  "crs": "EPSG:4326",
  "scheme": "tms",
  "license": "CC-BY-4.0",
  "updated_at": "2026-09-20T00:00:00Z",
  "tiles": [
    {"z": 2, "x": 0, "y": 0, "path": "tiles/2/0/0.png", "blob_hash": "sha256:..."}
  ]
}
```

每个瓦片必须提供 SHA-256 `blob_hash`。包许可必填，瓦片可用自己的 `license` 覆盖。上传后先进入“待确认”；接受后的瓦片才会进入候选池。重复覆盖、日期倒置、空洞、像素接缝以及“边界像素相同但元数据/授权不同”的冲突会写入每个输出瓦片的 provenance。

## 状态与幂等

每次状态变化都会向 `events.log` 追加一条 JSON 事件并 fsync。旧状态不会原地覆盖；重放事件得到当前状态。

上传、审核、规则、构建和导入接口都接受 `Idempotency-Key` HTTP 头。同一个键重复到达时返回第一次已经确定的状态；即使第二次请求体不同，也不会生成第二个结果。

网页分开显示：待确认、已接受、被拒绝，以及恢复中的构建。

## 内容寻址发布和中断恢复

- 输入与输出瓦片都放在 `cas/sha256/<xx>/<hash>`，路径由 `sha256:` 哈希确定。
- 构建先逐块写入 CAS；每个已写块都有 `build_block_written` 事件。
- 发布清单先写为 `builds/<id>.staging.json`，清单完成、事件提交后才原子改名为 `builds/<id>.json`，所以未完成的发布清单不可见。
- 如果进程在块写入期间退出，重启时 `building` 构建会转成 `recovering`；也可以在网页点“恢复/重试”或调用 `POST /api/builds/{id}/recover`。
- 恢复会验证已存在块；有效块跳过继续，损坏或缺失块重新写。写入失败时事件日志和旧的已发布状态仍可读取。

## 导出/重新导入

已发布构建可通过网页导出或：

```bash
curl -OJ http://127.0.0.1:5218/api/builds/<build-id>/export
```

导出 ZIP 含确定性 `build.json`、包来源摘要和所有输出内容块。重新导入会重算清单和块哈希；通过验证后得到相同的瓦片编号、范围边界、来源摘要和 build id。

## 测试

```bash
go test ./... -count=1
```

测试覆盖反子午线、极区、TMS、越界隔离、元数据冲突、重复/日期倒置、事件幂等、CAS 写失败后的旧状态可读性与恢复，以及导出再导入等价性。
